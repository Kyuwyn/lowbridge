# Paper pacing model

This is the calculation model used for the worked budget, not game code or a test of player behavior. Durations, purchase allowances, a 20% reduction of eligible village practice, evenly spaced visits, and one-minute selection/spending allowances are provisional inputs.

`pacing-model.py` reproduces the baseline two/three-visits-per-day comparisons with 48- and 72-hour caps, and the cumulative reserve calculation. It uses only the Python standard library. Run `python3 pacing-model.py` if desired. It prints the results and writes `results-regenerated.json` beside itself.

For portability, this copy adds a `pathlib.Path` import and changes only the original temporary output location to a path beside the script. The model and inputs are otherwise unchanged. `recorded-results.json` is the actual output retained from the original calculation.

`recorded-visit-sensitivity.json` records the additional 5-, 10-, and 15-minute-visit runs at a 48-hour cap using the same `simulate` function. Those results can be regenerated by calling `simulate(focused_or_curious_tasks, interval_hours, 48, visit_minutes / 60)` for intervals 12 and 8 and visit lengths 5, 10, and 15.

The assertions check completed-work totals and time conservation. They do not validate the design, actual interface effort, economic costs, or enjoyment. See [the worked budget](../../design/PACING-PAPER-BUDGET.md) for the interpretation.
